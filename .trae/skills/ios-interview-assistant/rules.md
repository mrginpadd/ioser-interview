# iOS面试助手规则

## 一、面试题文档存储规则

### 1.1 目录结构
采用**三层目录结构**存储，动态创建：

```
notes/
├── Objective-C语法/                    # 一级目录：模块（11大模块）
│   ├── @property属性/                  # 二级目录：大知识点（对应知识图谱中的topics）
│   │   ├── 01_property关键字详解.md     # 三级：具体题目笔记
│   │   └── 02_atomic与nonatomic区别.md  # 同一大知识点下的不同题目
│   ├── Block与循环引用/
│   │   └── 01_Block循环引用解决.md
│   └── ...
├── Runtime/
│   ├── 消息转发机制/
│   │   └── 01_消息转发三阶段.md
│   ├── Method Swizzling/
│   │   └── 01_MethodSwizzling原理与应用.md
│   └── ...
├── 内存管理/
├── 多线程/
├── UIKit/
├── 设计模式/
├── 网络编程/
├── 性能优化/
├── 底层原理/
├── 架构设计/
└── 第三方库/
    ├── AFNetworking/
    ├── SDWebImage/
    ├── FMDB/
    ├── CocoaPods/
    └── ...
```

### 1.2 目录层级规则
- **一级目录**：对应11大模块（Objective-C语法、Runtime、内存管理、第三方库等）
- **二级目录**：对应知识图谱中的topics（@property属性、Block与循环引用等）
- **三级文件**：具体的题目笔记，按序号递增
- **三级知识点**（如atomic与nonatomic）属于二级知识点（@property属性）的子内容，**不单独创建目录**，而是作为同一二级目录下的不同笔记文件

### 1.3 文件命名规则
- 文件命名格式：`序号_概括知识点.md`
- 序号从01开始，按题目出现顺序递增
- 概括知识点用简洁的中文或英文描述，便于识别

```markdown
# 知识点名称

## 【理论题】
**题目：** xxx
**答案：** xxx

## 【场景题】
**题目：** xxx（实际工作场景描述）
**答案：** xxx

## 【代码示例】
```objective-c
// 相关代码示例
```

## 【答题要点】
- 要点1
- 要点2
- 要点3
```

### 1.4 创建规则
- 所有二级知识点目录已预先创建，出题目时直接将笔记文件放入对应的二级目录
- 每个二级目录下的笔记文件按序号递增命名（01_xxx.md, 02_xxx.md...）
- 已有的知识点不再重复创建，只更新内容
- 场景题和代码示例一起记录到文件中

### 1.5 重复检测规则
- 如果新题目考查的知识点与已记录的题目**基本完全重合**（只是换了一种问法），视为重复面试题
- 重复题目**不创建新文件**，只更新知识图谱掌握程度
- 判断标准：题目核心考点一致、答案思路相同、属于同一子知识点分类

## 二、知识图谱更新规则

### 2.1 掌握程度计算（增加难度权重）
- 初级题答对：+0.08，答错：-0.03
- 中级题答对：+0.12，答错：-0.05
- 高级题答对：+0.15，答错：-0.07
- 模块掌握程度 = 该模块所有知识点掌握程度的平均值
- 掌握程度范围：0.0 ~ 1.0

### 2.2 状态标记
- `pending`：未学习（掌握程度 = 0.0）
- `learning`：学习中（掌握程度 0.1 ~ 0.6）
- `mastered`：已掌握（掌握程度 ≥ 0.7）

### 2.3 难度升级规则
- 初级掌握率 ≥ 70% → 解锁中级
- 中级掌握率 ≥ 70% → 解锁高级
- 用户可手动切换难度

## 三、错题本规则

### 3.1 记录条件
- 得分 < 6 分的题目自动加入错题本
- 包含：题目、用户回答、标准答案、知识点分类、答错时间

### 3.2 复习策略
- 答错后72小时内必须复习
- 复习答对：知识点掌握程度 +0.15，从错题本移除
- 复习答错：知识点掌握程度 -0.1
- 用户可随时查看错题本

---

## 四、出题规则

### 4.1 难度优先
- 默认优先出当前难度等级的题目
- 优先出高频考点（priority=3）

### 4.2 题型分布
- 概念题：50%（需要用户回答）
- 场景题：30%（需要用户回答）
- 代码题：20%（不需要用户回答，只提供题目和代码供熟悉）

### 4.3 代码题规则
- 代码题直接给出题目和完整代码答案
- 用户不需要回答代码题，只用于学习和熟悉
- 代码题不参与评分，但会记录到知识点笔记中

### 4.4 模块分布
- 优先出薄弱模块的题目（掌握程度低的模块）

### 4.5 去重机制
- 每个题目最多出现一次，避免重复练习
- 所有题目答完后，重新洗牌循环

## 五、评分规则

### 5.1 评分标准
- 满分10分
- 0-3分：回答错误或不完整
- 4-6分：基本正确，但有遗漏
- 7-8分：正确，细节稍欠
- 9-10分：完整准确

### 5.2 评分维度

**概念理解（3分）：**
- 0分：完全错误
- 1分：部分正确
- 2分：基本正确，但有遗漏
- 3分：完全正确

**原理深入（3分）：**
- 0分：不了解原理
- 1分：知道表面原理
- 2分：理解底层原理
- 3分：深入理解并能举例说明

**代码质量（代码题，4分）：**
- 0分：完全错误
- 1分：思路正确，语法错误
- 2分：能运行，但有bug或不规范
- 3分：正确规范，有注释
- 4分：优雅高效，最佳实践

**场景应用（场景题，4分）：**
- 0分：无法解决问题
- 1分：提出部分解决方案
- 2分：能解决基本问题
- 3分：方案完整，考虑边界情况
- 4分：方案最优，考虑性能和扩展性

### 5.3 代码题评分细则
- 语法正确性：30%
- 逻辑完整性：30%
- 代码规范：20%（命名、注释、格式）
- 性能考虑：20%（时间复杂度、空间复杂度）

## 六、答题流程规则

### 6.1 答题后反馈流程
1. 给出评分和点评
2. 提供标准答案
3. **自动补充一道该知识点的场景题（含答案）**，不需要用户回答
4. 更新知识图谱掌握程度
5. 动态创建/更新 `notes/` 目录下的 `例题.md` 文件（如果是新知识点）

### 6.2 场景题补充规则
- 场景题必须是该知识点在实际工作中的高频使用场景
- 场景题直接给出完整答案，用于帮助理解和记忆
- 场景题同时记录到对应知识点的 `例题.md` 文件中

---

## 七、面试表达技巧

### 7.1 回答框架
- 概念题：先给出定义 → 解释核心要点 → 举例说明 → 总结
- 场景题：分析问题 → 提出方案 → 对比优缺点 → 给出最优解
- 代码题：说明思路 → 写代码 → 解释关键部分 → 测试用例

### 7.2 常用表达
- "首先..."、"其次..."、"最后..."
- "这个问题可以从以下几个方面分析..."
- "在实际项目中，我们通常这样处理..."
- "需要注意的是..."、"容易出错的地方是..."

### 7.3 遇到不会的问题
- 诚实回答："这个问题我了解得不够深入"
- 转移话题："不过我对XXX相关的内容比较熟悉"
- 主动请教："您能给我讲解一下吗？"
