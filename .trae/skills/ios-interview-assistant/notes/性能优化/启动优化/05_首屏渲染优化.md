# 首屏渲染优化

## 【理论题】
**题目：** 请解释首屏渲染的优化方向，以及如何减少首屏加载时间？
**答案：**

**首屏渲染流程：**

```
首屏渲染时间线：
main() → 创建根VC → viewDidLoad → 计算布局 → 渲染视图 → 首屏显示

优化目标：减少从main()到首屏显示的时间
```

**优化方向：**

| 优化方向 | 具体方法 |
|---------|---------|
| **简化首屏VC** | 减少视图层级、移除非首屏元素 |
| **占位图** | 使用Launch Screen或自定义占位图 |
| **异步加载** | 图片、数据异步加载 |
| **缓存首屏数据** | 上次启动缓存首屏数据 |
| **简化布局** | 减少AutoLayout约束、使用纯代码布局 |
| **懒加载子视图** | 非首屏可见区域的视图懒加载 |

**为什么首屏渲染会慢？**

```
首屏渲染耗时构成：
├── 创建视图（50ms）
├── 计算布局（100ms）
├── 加载图片（200ms）❌ 主要耗时
├── 网络请求（500ms）❌ 主要耗时
└── 渲染视图（50ms）

总耗时：900ms

优化后：
├── 创建视图（50ms）
├── 计算布局（50ms）
├── 显示占位图（10ms）
└── 总耗时：110ms ✅

后台异步：
├── 加载图片（200ms）
└── 网络请求（500ms）
```

## 【场景题】
**题目：** 如何优化TableView的首屏加载？

**答案：**

| 优化方法 | 说明 |
|---------|------|
| **缓存cell高度** | 计算一次后缓存，避免重复计算 |
| **预加载数据** | 提前获取首屏数据 |
| **简化cell** | 减少子视图数量 |
| **异步渲染** | 复杂视图异步绘制 |
| **使用estimatedHeight** | 减少布局计算 |

## 【代码示例】
```objective-c
// ✅ 使用占位图
- (void)viewDidLoad {
    [super viewDidLoad];
    
    // 显示占位图
    self.placeholderView.hidden = NO;
    
    // 异步加载数据
    [self fetchDataAsync];
}

- (void)fetchDataAsync {
    dispatch_async(dispatch_get_global_queue(0, 0), ^{
        // 网络请求获取数据
        NSArray *data = [APIClient fetchHomePageData];
        
        dispatch_async(dispatch_get_main_queue(), ^{
            // 更新UI
            self.dataArray = data;
            [self.tableView reloadData];
            
            // 隐藏占位图
            self.placeholderView.hidden = YES;
        });
    });
}

// ✅ 缓存首屏数据
- (void)cacheFirstPageData:(NSArray *)data {
    // 缓存到本地
    NSUserDefaults *defaults = [NSUserDefaults standardUserDefaults];
    [defaults setObject:[NSKeyedArchiver archivedDataWithRootObject:data] 
                 forKey:@"firstPageCache"];
    [defaults synchronize];
}

- (NSArray *)loadCachedFirstPageData {
    NSUserDefaults *defaults = [NSUserDefaults standardUserDefaults];
    NSData *data = [defaults objectForKey:@"firstPageCache"];
    if (data) {
        return [NSKeyedUnarchiver unarchiveObjectWithData:data];
    }
    return nil;
}

// ✅ 简化视图层级
// 不好的做法：多层嵌套
// UIView → UIView → UILabel
// 好的做法：直接添加到父视图
// UIView → UILabel

// ✅ 懒加载子视图
- (void)setupSubviews {
    // 首屏可见区域的视图立即创建
    [self createVisibleViews];
    
    // 首屏不可见区域的视图懒加载
    self.lazyView = nil;
}

- (LazyView *)lazyView {
    if (!_lazyView) {
        _lazyView = [[LazyView alloc] init];
        [self.view addSubview:_lazyView];
    }
    return _lazyView;
}

// ✅ TableView优化：缓存cell高度
@property (nonatomic, strong) NSMutableDictionary *heightCache;

- (CGFloat)tableView:(UITableView *)tableView heightForRowAtIndexPath:(NSIndexPath *)indexPath {
    NSNumber *cachedHeight = self.heightCache[@(indexPath.row)];
    if (cachedHeight) {
        return [cachedHeight floatValue];
    }
    
    // 计算高度
    CGFloat height = [self calculateCellHeightForIndexPath:indexPath];
    self.heightCache[@(indexPath.row)] = @(height);
    return height;
}

// ✅ 使用estimatedHeight减少布局计算
- (void)setupTableView {
    self.tableView.estimatedRowHeight = 100;
    self.tableView.rowHeight = UITableViewAutomaticDimension;
}

// ✅ 预加载数据（在didLaunching中）
- (BOOL)application:(UIApplication *)application 
    didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
    
    // 提前获取首屏数据
    [APIClient prefetchHomePageData];
    
    return YES;
}
```

## 【答题要点】
- 首屏渲染优化：简化视图、占位图、异步加载、缓存数据
- 主要耗时点：图片加载、网络请求、布局计算
- 使用占位图快速显示首屏
- 数据和图片异步加载
- 缓存上次首屏数据，快速展示
- TableView优化：缓存高度、estimatedHeight、简化cell
- 视图层级尽量扁平，减少嵌套
- 非首屏可见区域的视图懒加载
- 预加载首屏数据
