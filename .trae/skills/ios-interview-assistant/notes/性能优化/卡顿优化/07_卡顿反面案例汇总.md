# 卡顿反面案例汇总

## 【案例1：主线程同步网络请求】

**错误代码：**
```objective-c
- (void)viewDidLoad {
    [super viewDidLoad];
    
    // ❌ 在主线程执行同步网络请求
    NSURL *url = [NSURL URLWithString:@"https://example.com/api/data"];
    NSData *data = [NSData dataWithContentsOfURL:url]; // 阻塞主线程！
    self.json = [NSJSONSerialization JSONObjectWithData:data options:0 error:nil];
    
    // UI更新（可能已经卡顿）
    [self updateUI];
}
```

**问题分析：**
```
问题原因：
├── [NSData dataWithContentsOfURL:] 是同步方法
├── 网络请求可能需要几百毫秒到几秒
├── 主线程被阻塞期间无法响应用户操作
├── 屏幕无法刷新，出现卡顿/假死

后果：
├── App界面冻结，用户无法操作
├── 可能导致Watchdog超时崩溃
├── 用户体验极差
```

## 【案例2：for循环中重复创建对象】

**错误代码：**
```objective-c
- (void)processData {
    NSMutableArray *results = [NSMutableArray array];
    
    // ❌ 在for循环中每次都创建新对象
    for (NSInteger i = 0; i < 10000; i++) {
        NSString *item = [NSString stringWithFormat:@"Item %ld", (long)i];
        [results addObject:item];
    }
}
```

**问题分析：**
```
问题原因：
├── 每次循环都创建新的NSString对象
├── 创建10000个临时对象
├── ARC需要频繁管理这些对象的生命周期
├── 增加内存分配和GC压力

后果：
├── 内存峰值飙升
├── 触发频繁的内存回收（GC）
├── GC过程会阻塞主线程，导致卡顿
```

## 【案例3：TableView不使用cell复用】

**错误代码：**
```objective-c
- (UITableViewCell *)tableView:(UITableView *)tableView cellForRowAtIndexPath:(NSIndexPath *)indexPath {
    // ❌ 每次都创建新的cell
    UITableViewCell *cell = [[UITableViewCell alloc] initWithStyle:UITableViewCellStyleDefault reuseIdentifier:@"Cell"];
    cell.textLabel.text = self.dataArray[indexPath.row];
    return cell;
}
```

**问题分析：**
```
问题原因：
├── 滚动时每次都创建新的cell对象
├── 创建和销毁大量cell
├── 增加内存分配和释放的开销
├── 大量的视图层级操作

后果：
├── 内存占用飙升
├── 滚动时卡顿明显
├── CPU占用率高
```

## 【案例4：离屏渲染滥用】

**错误代码：**
```objective-c
- (void)setupViews {
    UIView *cardView = [[UIView alloc] initWithFrame:CGRectMake(20, 20, 280, 100)];
    
    // ❌ 同时设置圆角和阴影，触发离屏渲染
    cardView.layer.cornerRadius = 10;
    cardView.layer.masksToBounds = YES;
    cardView.layer.shadowColor = [UIColor blackColor].CGColor;
    cardView.layer.shadowOpacity = 0.5;
    cardView.layer.shadowRadius = 5;
    
    [self.view addSubview:cardView];
}
```

**问题分析：**
```
问题原因：
├── masksToBounds = YES + cornerRadius → 离屏渲染
├── shadow（未设置shadowPath）→ 离屏渲染
├── 两种离屏渲染叠加，性能更差
├── GPU需要额外的缓冲区和渲染步骤

后果：
├── GPU负载过高
├── 帧率下降（FPS < 60）
├── 滚动或动画时卡顿
```

## 【案例5：AutoLayout约束过多】

**错误代码：**
```objective-c
- (void)setupConstraints {
    // ❌ 使用大量复杂的AutoLayout约束
    NSDictionary *views = NSDictionaryOfVariableBindings(_view1, _view2, _view3, _view4, _view5);
    
    [self.view addConstraints:[NSLayoutConstraint constraintsWithVisualFormat:@"H:|-20-[_view1]-10-[_view2]-10-[_view3]-10-[_view4]-10-[_view5]-20-|" options:0 metrics:nil views:views]];
    [self.view addConstraints:[NSLayoutConstraint constraintsWithVisualFormat:@"V:|-20-[_view1]-20-|" options:0 metrics:nil views:views]];
    [self.view addConstraints:[NSLayoutConstraint constraintsWithVisualFormat:@"V:|-20-[_view2]-20-|" options:0 metrics:nil views:views]];
    // ... 更多约束
    
    // 每次更新约束都需要重新计算
    [self.view layoutIfNeeded];
}
```

**问题分析：**
```
问题原因：
├── AutoLayout需要求解约束方程
├── 约束越多，计算复杂度越高（O(n^2)）
├── 每次布局变化都需要重新计算
├── 在滚动或动画时频繁触发

后果：
├── CPU计算耗时增加
├── 布局更新延迟
├── 滚动时卡顿
```

## 【案例6：重复调用layoutIfNeeded】

**错误代码：**
```objective-c
- (void)animateViews {
    // ❌ 在循环中多次调用layoutIfNeeded
    for (NSInteger i = 0; i < 50; i++) {
        _view.frame = CGRectMake(i * 10, 0, 100, 100);
        [_view layoutIfNeeded]; // 每次循环都触发布局计算
    }
}
```

**问题分析：**
```
问题原因：
├── 每次调用layoutIfNeeded都会触发完整的布局计算
├── 50次循环触发50次布局计算
├── 布局计算是CPU密集型操作
├── 浪费大量CPU资源

后果：
├── CPU占用率飙升
├── 动画卡顿不流畅
├── 主线程阻塞
```
