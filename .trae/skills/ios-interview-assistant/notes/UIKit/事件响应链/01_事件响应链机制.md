# 事件响应链

## 【理论题】
**题目：** 请解释iOS的事件响应链机制，以及触摸事件是如何传递的？
**答案：**

**事件响应链机制：**

**事件处理分为两个阶段：事件传递（从父到子）+ 事件响应（从子到父）**

**事件传递阶段（hit-testing）：从外到内，找最合适的响应者**

核心方法：
- `hitTest:withEvent:` - 查找最合适的view
- `pointInside:withEvent:` - 判断点是否在view内

流程：
1. 先判断自己能否接收事件（userInteractionEnabled）
2. 判断点是否在自己范围内（pointInside）
3. 从后往前遍历子视图（后添加的先遍历）
4. 递归调用子视图的hitTest
5. 返回最合适的view

**事件响应阶段（responder chain）：从内到外，找能处理的对象**

核心方法：
- `touchesBegan:withEvent:`
- `touchesMoved:withEvent:`
- `touchesEnded:withEvent:`
- `nextResponder` - 下一个响应者

流程：
1. 从最合适的view开始处理
2. 不能处理就交给nextResponder
3. 一直传递到UIApplication
4. 都不能处理就丢弃事件

**核心方法对比：**

| 方法 | 作用 |
|------|------|
| `hitTest:withEvent:` | 查找最合适的响应者view |
| `pointInside:withEvent:` | 判断触摸点是否在view范围内 |
| `nextResponder` | 获取下一个响应者 |
| `touchesBegan/Moved/Ended/Cancelled` | 处理触摸事件 |

## 【常见疑问】

### Q：为什么事件传递和事件响应的顺序是反的？

**A：因为两个阶段解决的是不同的问题。**

| 阶段 | 方向 | 解决的问题 |
|------|------|-----------|
| 事件传递 | 外 → 内 | **谁最合适？**（找到最应该响应的view） |
| 事件响应 | 内 → 外 | **谁能处理？**（找到能处理事件的对象） |

**类比：**
- 事件传递 = 找负责人（从大领导往下找，找到具体执行人）
- 事件响应 = 谁能解决（从执行人往上找，找到能解决问题的人）

**iOS例子：**
```
页面结构：ViewController.view → scrollView → contentView → button

点击button：
【事件传递】外→内：找到button（最合适的响应者）
【事件响应】内→外：button自己就能处理，直接响应

如果是点击label（label不能处理点击）：
【事件传递】外→内：找到label（最合适的响应者）
【事件响应】内→外：label不能处理 → 交给superview处理
```

## 【场景题】
**题目：** 如何实现一个超出父视图范围的按钮也能响应点击？

**答案：**

重写父视图的`hitTest:withEvent:`方法，扩大点击区域。

```objective-c
// ParentView.m
- (UIView *)hitTest:(CGPoint)point withEvent:(UIEvent *)event {
    // 先判断自己能否接收
    if (!self.userInteractionEnabled || self.hidden || self.alpha <= 0.01) {
        return nil;
    }
    
    // 遍历子视图，检查按钮是否被点击
    for (UIView *subview in self.subviews.reverseObjectEnumerator) {
        // 将点转换到子视图坐标系
        CGPoint subPoint = [self convertPoint:point toView:subview];
        // 递归调用子视图的hitTest
        UIView *result = [subview hitTest:subPoint withEvent:event];
        if (result) {
            return result;
        }
    }
    
    // 判断点是否在自己范围内
    if ([self pointInside:point withEvent:event) {
        return self;
    }
    
    return nil;
}
```

**应用场景：**
1. **扩大按钮点击区域**（小按钮增大点击范围）
2. **超出父视图范围的子视图也能响应**
3. **特殊形状的点击区域**（圆形、不规则形状）

## 【代码示例】
```objective-c
// 1. 扩大按钮点击区域
@interface EnlargedButton : UIButton
@end

@implementation EnlargedButton

- (BOOL)pointInside:(CGPoint)point withEvent:(UIEvent *)event {
    // 扩大点击区域10pt
    CGRect bounds = self.bounds;
    bounds = CGRectInset(bounds, -10, -10);
    return CGRectContainsPoint(bounds, point);
}

@end

// 2. 事件拦截（自定义事件
- (void)touchesBegan:(NSSet<UITouch *> *)touches withEvent:(UIEvent *)event {
    UITouch *touch = [touches anyObject];
    CGPoint point = [touch locationInView:self];
    NSLog(@"touches began at point: %@", NSStringFromCGPoint(point));
    
    // 不调用super，事件不再传递
    // [super touchesBegan:touches withEvent:event];
}

// 3. 事件穿透（让事件透传到下面的view
- (UIView *)hitTest:(CGPoint)point withEvent:(UIEvent *)event {
    UIView *result = [super hitTest:point withEvent:event];
    if (result == self) {
        return nil; // 不响应，让下面的view响应
    }
    return result;
}
```

## 【答题要点】
- 事件处理分两个阶段：事件传递 + 事件响应
- 事件传递：从外到内（父→子），找最合适的响应者
- 事件响应：从内到外（子→父），找能处理的对象
- hitTest:withEvent: 是找最合适的view
- pointInside:withEvent: 判断点是否在范围内
- 不能接收事件的条件：userInteractionEnabled=YES、hidden=NO、alpha>0.01
- 响应者链：view → viewController → window → application
- 常见应用：扩大点击区域、穿透点击、事件拦截
