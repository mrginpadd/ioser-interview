# 循环引用

## 【理论题】
**题目：** 请解释循环引用（Retain Cycle）的概念，以及如何解决循环引用问题？
**答案：**

**循环引用的概念：**

> 对象被引用时引用计数+1，引用被释放时引用计数-1，引用计数归0时释放对象。
>
> **循环引用 = 引用链条形成闭环，每个对象都被其他对象引用，导致引用计数永远无法归0，对象无法释放。**

```
正常引用链（可以释放）：
A → B → C
（A释放，B的引用计数-1，B释放，C的引用计数-1）

循环引用（无法释放）：
A → B → A
（A引用B，B引用A，形成闭环，双方引用计数都不为0）
```

**常见循环引用场景：**

| 场景 | 说明 |
|------|------|
| **delegate** | 对象强引用delegate，delegate强引用对象 |
| **block** | block捕获self，self强引用block |
| **NSTimer** | timer强引用target，target强引用timer |
| **嵌套block** | 多个block互相捕获 |
| **通知/KVO** | observer和被观察对象互相强引用 |

**解决方法：**

| 方法 | 作用 | 适用场景 |
|------|------|---------|
| `__weak` | 弱引用，不增加引用计数，对象释放后自动置nil | delegate、block、timer |
| `__unsafe_unretained` | 弱引用，不增加引用计数，对象释放后变成野指针 | 性能要求高的场景 |
| `__autoreleasing` | 用于函数参数返回对象的所有权管理 | 方法参数 |
| 手动断开 | 在合适时机主动断开引用 | NSTimer的invalidate |

## 【场景题】
**题目：** delegate为什么要用weak而不是strong？

**答案：**

```
用strong的情况（循环引用）：
ViewController → strong → customView
customView → strong → delegate（ViewController）
↑_______________________________________|
形成循环引用，双方都无法释放

用weak的情况（正常释放）：
ViewController → strong → customView
customView → weak → delegate（ViewController）
ViewController释放后，customView的delegate自动置nil，customView也能正常释放
```

## 【代码示例】
```objective-c
// 1. delegate中的循环引用（错误写法）
@interface CustomView : UIView
@property (nonatomic, strong) id<CustomViewDelegate> delegate;  // 错误：strong导致循环引用
@end

// 正确写法
@property (nonatomic, weak) id<CustomViewDelegate> delegate;  // 正确：weak

//因为设置代理时是self.delegate = self , 循环引用，用weak打断。

// 2. block中的循环引用（错误写法）
@interface ViewController : UIViewController
@property (nonatomic, copy) void(^myBlock);
@end

@implementation ViewController
- (void)viewDidLoad {
    [super viewDidLoad];
    
    self.myBlock = ^{
        [self doSomething];  // 错误：block捕获self，形成循环引用
        // self → strong → block
        // block → strong → self
    };
}
@end

// 正确写法：__weak
- (void)viewDidLoad {
    [super viewDidLoad];
    
    __weak typeof(self) weakSelf = self;
    self.myBlock = ^{
        __strong typeof(weakSelf) strongSelf = weakSelf;
        if (strongSelf) {
            [strongSelf doSomething];
        }
    };
}

// 3. NSTimer的循环引用（错误写法）
@interface ViewController : UIViewController
@property (nonatomic, strong) NSTimer *timer;
@end

@implementation ViewController
- (void)startTimer {
    self.timer = [NSTimer scheduledTimerWithTimeInterval:1.0 
                                                  target:self 
                                                selector:@selector(tick) 
                                                userInfo:nil 
                                                 repeats:YES];
    // 错误：self强引用timer，timer强引用target（self）
}
@end

// 正确写法：使用target或invalidate
- (void)dealloc {
    [self.timer invalidate];  // 在dealloc之前调用invalidate断开引用
    self.timer = nil;
}

// 或使用iOS 10+的block API
- (void)startTimer {
    __weak typeof(self) weakSelf = self;
    self.timer = [NSTimer scheduledTimerWithTimeInterval:1.0 
                                               repeats:YES 
                                              block:^(NSTimer * _Nonnull timer) {
        __strong typeof(weakSelf) strongSelf = weakSelf;
        [strongSelf tick];
    }];
}

// 4. 通知的循环引用
// 注意：iOS 9+以后，通知中心对observer是弱引用，不会造成循环引用
// 但如果block形式的通知需要注意

// 5. KVO的循环引用
// KVO中，被观察对象不会强引用观察者，不会造成循环引用
// 但观察者需要在dealloc中removeObserver

// 6. 手动断开引用
- (void)dealloc {
    [[NSNotificationCenter defaultCenter] removeObserver:self];
    [self.timer invalidate];
    self.timer = nil;
}
```

## 【答题要点】
- 循环引用 = 引用链形成闭环，引用计数无法归0
- 常见场景：delegate、block、NSTimer
- 解决方法：__weak、__unsafe_unretained、手动断开
- __weak不增加引用计数，对象释放后自动置nil
- __unsafe_unretained不增加引用计数，对象释放后变野指针
- delegate要用weak
- block中用__weak typeof(self) weakSelf = self
- NSTimer要在dealloc前invalidate
- 循环引用是内存泄漏的主要原因之一
