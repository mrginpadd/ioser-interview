## 一、Objective-C语法

### 1.1 @property属性

**【理论题1】请解释@property的作用？**

答：@property是Objective-C的属性声明语法，编译器会自动生成：
1. 实例变量（ivar）
2. getter方法
3. setter方法

完整写法：`@property (nonatomic, strong) NSString *name;`

**【理论题2】@property的属性关键字有哪些？各自有什么作用？**

答：常用属性关键字：
- `atomic` / `nonatomic`：原子性控制
- `strong` / `weak` / `assign` / `copy`：内存管理语义
- `readwrite` / `readonly`：读写权限
- `getter=xxx` / `setter=xxx`：自定义访问器方法名

**【场景题】在多线程环境下，使用atomic属性是否就一定是线程安全的？为什么？**

答：不一定。atomic仅保证属性的getter/setter操作是原子的（即读写操作完整），但不保证线程安全。

场景示例：
```objc
// 多个线程同时执行
self.counter = self.counter + 1;
```
这行代码包含三个操作：getter读取、+1计算、setter写入。虽然每个操作是atomic的，但整体不是原子操作，可能导致线程安全问题。

**【代码示例】自定义getter和setter**
```objc
@property (nonatomic, strong) NSString *name;

- (NSString *)name {
    return _name;
}

- (void)setName:(NSString *)name {
    _name = [name copy];
}
```

### 1.2 atomic与nonatomic

**【理论题】atomic和nonatomic的区别？**

答：
- **atomic**：原子属性，编译器生成的getter/setter会保证读写操作的原子性。在多线程环境下，不会出现读取到不完整数据的情况，但性能较低。
- **nonatomic**：非原子属性，不保证原子性，性能更高。需要开发者手动保证线程安全。

**【场景题】项目中应该如何选择atomic和nonatomic？**

答：
- **日常开发**：优先使用nonatomic，性能更好，且大多数场景不需要atomic的保护
- **需要线程安全的场景**：不要依赖atomic，应使用锁（如@synchronized、NSLock等）来保证真正的线程安全
- **性能敏感场景**：必须使用nonatomic

**【代码示例】atomic的局限性**
```objc
@property (atomic, assign) NSInteger count;

// 多线程下仍不安全
self.count = self.count + 1; 
// 等价于：
// NSInteger temp = [self count]; // atomic
// temp = temp + 1;
// [self setCount:temp]; // atomic
// 但整体不是原子操作
```

### 1.3 Block与循环引用

**【理论题】什么是Block循环引用？如何解决？**

答：当Block内部引用了self，而self又持有这个Block时，会形成循环引用，导致内存泄漏。

解决方法：使用__weak + __strong dance

**【理论题2】Block的三种类型是什么？**

答：
1. **NSGlobalBlock**：不捕获外部变量，存储在全局区
2. **NSStackBlock**：捕获外部变量，存储在栈上（MRC下）
3. **NSMallocBlock**：捕获外部变量，存储在堆上（ARC下）

**【场景题】在ViewController中使用Block时，哪些情况会产生循环引用？**

答：以下情况会产生循环引用：
```objc
// 情况1：Block作为属性
@property (nonatomic, copy) void(^completionBlock)(void);

- (void)doSomething {
    self.completionBlock = ^{
        [self updateUI]; // 循环引用
    };
}

// 情况2：Block作为参数传递给持有self的对象
[self.networkManager requestWithCompletion:^{
    [self updateData]; // 如果networkManager被self持有，可能循环引用
}];
```

**【代码示例】__weak + __strong dance**
```objc
__weak typeof(self) weakSelf = self;
self.completionBlock = ^{
    __strong typeof(weakSelf) strongSelf = weakSelf;
    if (strongSelf) {
        [strongSelf updateUI];
    }
};
```

### 1.4 分类与扩展

**【理论题】分类（Category）和扩展（Extension）的区别？**

答：
| 特性 | Category | Extension |
|------|----------|-----------|
| 声明位置 | 独立文件 | 类实现文件中 |
| 能否添加实例变量 | 不能 | 能 |
| 方法实现 | 需要在分类文件中实现 | 在类的主实现中 |
| 可见性 | 默认对外可见 | 默认私有 |

**【场景题】什么时候使用分类？什么时候使用扩展？**

答：
- **分类**：为已有类添加功能，如为NSString添加加密方法、为UIViewController添加通用导航方法
- **扩展**：为类添加私有属性和方法，隐藏实现细节

**【代码示例】分类和扩展**
```objc
// NSString+Encryption.h
@interface NSString (Encryption)
- (NSString *)md5;
@end

// ViewController.m
@interface ViewController ()
@property (nonatomic, strong) NSString *privateData;
- (void)privateMethod;
@end
```

### 1.5 协议与代理

**【理论题】协议（Protocol）是什么？有什么作用？**

答：协议是一组方法的声明集合，用于定义接口规范，实现解耦。协议可以分为：
- **正式协议**：使用@protocol声明
- **非正式协议**：通过分类实现

**【场景题】代理模式的使用场景有哪些？**

答：
- 反向传值：如TableView的didSelectRow回调
- 事件通知：如自定义控件的点击事件
- 解耦：降低组件间的耦合度

**【代码示例】代理模式**
```objc
@protocol CustomViewDelegate <NSObject>
- (void)customView:(CustomView *)view didTapButton:(UIButton *)button;
@end

@interface CustomView : UIView
@property (nonatomic, weak) id<CustomViewDelegate> delegate;
@end

@implementation CustomView
- (void)buttonTapped {
    if ([self.delegate respondsToSelector:@selector(customView:didTapButton:)]) {
        [self.delegate customView:self didTapButton:self.button];
    }
}
@end
```

### 1.6 消息机制

**【理论题】Objective-C的消息发送机制是什么？**

答：Objective-C的方法调用实际上是消息发送：
```objc
[obj method]; // 编译后变为：objc_msgSend(obj, @selector(method))
```

消息发送流程：
1. 查找方法缓存（cache）
2. 查找方法列表（method list）
3. 消息转发（动态方法解析 → 备用接收者 → 完整消息转发）

**【场景题】当调用一个不存在的方法时，会发生什么？**

答：会触发消息转发机制：
1. 首先调用`+resolveInstanceMethod:`尝试动态添加方法
2. 如果返回NO，调用`-forwardingTargetForSelector:`尝试转发给其他对象
3. 如果返回nil，调用`-methodSignatureForSelector:`和`-forwardInvocation:`进行完整消息转发
4. 如果都失败，调用`-doesNotRecognizeSelector:`抛出异常

**【代码示例】动态方法解析**
```objc
+ (BOOL)resolveInstanceMethod:(SEL)sel {
    if (sel == @selector(dynamicMethod)) {
        class_addMethod(self, sel, (IMP)dynamicMethodIMP, "v@:");
        return YES;
    }
    return [super resolveInstanceMethod:sel];
}

void dynamicMethodIMP(id self, SEL _cmd) {
    NSLog(@"动态添加的方法");
}
```

### 1.7 SEL与IMP

**【理论题】SEL和IMP分别是什么？它们之间的关系？**

答：
- **SEL**：方法选择器，是方法名的唯一标识（字符串哈希值）
- **IMP**：方法实现指针，指向方法的实际代码

关系：SEL通过Runtime可以找到对应的IMP

**【场景题】如何通过SEL获取方法的实现？**

答：
```objc
IMP imp = [obj methodForSelector:@selector(methodName)];
void (*func)(id, SEL) = (void *)imp;
func(obj, @selector(methodName));
```

### 1.8 id与instancetype

**【理论题】id和instancetype的区别？**

答：
| 特性 | id | instancetype |
|------|----|--------------|
| 类型安全 | 无类型检查 | 有类型检查 |

**【代码示例】正确的初始化方法**
```objc
- (instancetype)initWithName:(NSString *)name {
    self = [super init];
    if (self) {
        _name = name;
    }
    return self;
}
```

### 1.9 NSCopying与NSMutableCopying

**【理论题】copy和mutableCopy的区别？**

答：
- **copy**：创建不可变副本（如NSString的copy返回NSString）
- **mutableCopy**：创建可变副本（如NSString的mutableCopy返回NSMutableString）

**【场景题】自定义类如何实现copy功能？**

答：需要遵守NSCopying协议，实现`-copyWithZone:`方法。

**【代码示例】实现NSCopying**
```objc
@interface Person : NSObject <NSCopying>
@property (nonatomic, copy) NSString *name;
@property (nonatomic, assign) NSInteger age;
@end

@implementation Person
- (id)copyWithZone:(NSZone *)zone {
    Person *copy = [[[self class] allocWithZone:zone] init];
    copy.name = self.name;
    copy.age = self.age;
    return copy;
}
@end
```

### 1.10 初始化方法

**【理论题】init方法的调用链是什么？**

答：
```objc
- (instancetype)init {
    self = [super init]; // 调用父类初始化
    if (self) {
        // 子类初始化
    }
    return self;
}
```

**【场景题】为什么在init方法中要先调用[super init]并检查self？**

答：
1. 调用[super init]确保父类完成初始化
2. 检查self是因为父类的init可能返回nil（如单例模式）或返回其他对象

**【代码示例】正确的初始化方法**
```objc
- (instancetype)initWithFrame:(CGRect)frame {
    self = [super initWithFrame:frame];
    if (self) {
        [self setupView];
    }
    return self;
}
```

## 二、Runtime

### 2.1 消息转发机制

**【理论题】消息转发的三个阶段是什么？**

答：
1. **动态方法解析**：调用`+resolveInstanceMethod:`或`+resolveClassMethod:`
2. **备用接收者**：调用`-forwardingTargetForSelector:`返回一个能处理该消息的对象
3. **完整消息转发**：调用`-methodSignatureForSelector:`获取方法签名，然后调用`-forwardInvocation:`转发消息

**【场景题】消息转发机制有什么实际应用？**

答：
- **方法拦截**：在不修改源码的情况下拦截方法调用
- **多继承模拟**：通过消息转发实现类似多继承的功能
- **容错处理**：对未实现的方法提供默认处理

**【代码示例】完整消息转发**
```objc
- (NSMethodSignature *)methodSignatureForSelector:(SEL)aSelector {
    NSMethodSignature *signature = [super methodSignatureForSelector:aSelector];
    if (!signature) {
        signature = [NSMethodSignature signatureWithObjCTypes:"v@:"];
    }
    return signature;
}

- (void)forwardInvocation:(NSInvocation *)anInvocation {
    if ([self.backupObject respondsToSelector:anInvocation.selector]) {
        [anInvocation invokeWithTarget:self.backupObject];
    } else {
        [self doesNotRecognizeSelector:anInvocation.selector];
    }
}
```

### 2.2 动态方法解析

**【理论题】如何动态添加方法？**

答：使用Runtime的`class_addMethod`函数：
```objc
class_addMethod(class, SEL, IMP, types);
```

**【场景题】动态方法解析的应用场景？**

答：
- **按需加载**：只在需要时才添加方法实现
- **方法替换**：在运行时替换方法实现
- **AOP编程**：在方法执行前后添加额外逻辑

**【代码示例】动态添加方法**
```objc
+ (BOOL)resolveInstanceMethod:(SEL)sel {
    if (sel == @selector(lazyMethod)) {
        class_addMethod(self, sel, (IMP)lazyMethodIMP, "v@:");
        return YES;
    }
    return [super resolveInstanceMethod:sel];
}

void lazyMethodIMP(id self, SEL _cmd) {
    NSLog(@"Lazy method called");
}
```

### 2.3 关联对象

**【理论题】什么是关联对象？如何使用？**

答：关联对象允许在运行时为对象动态添加属性，而不需要修改类的定义。

API：
- `objc_setAssociatedObject`：设置关联对象
- `objc_getAssociatedObject`：获取关联对象
- `objc_removeAssociatedObjects`：移除所有关联对象

**【场景题】关联对象的应用场景？**

答：
- **为分类添加属性**：分类不能添加实例变量，但可以通过关联对象模拟
- **临时存储数据**：在不修改类定义的情况下存储额外数据
- **状态管理**：为UI控件添加状态标记

**【代码示例】为分类添加属性**
```objc
#import <objc/runtime.h>

@interface UIViewController (AssociatedObject)
@property (nonatomic, strong) NSString *pageName;
@end

@implementation UIViewController (AssociatedObject)
- (void)setPageName:(NSString *)pageName {
    objc_setAssociatedObject(self, @selector(pageName), pageName, OBJC_ASSOCIATION_COPY_NONATOMIC);
}

- (NSString *)pageName {
    return objc_getAssociatedObject(self, @selector(pageName));
}
@end
```

### 2.4 Method Swizzling

**【理论题】什么是Method Swizzling？原理是什么？**

答：Method Swizzling是一种Runtime技术，用于在运行时交换两个方法的实现。

原理：通过修改类的方法列表，将原方法的IMP替换为新方法的IMP。

**【场景题】Method Swizzling的应用场景？**

答：
- **埋点统计**：在不修改业务代码的情况下添加统计逻辑
- **日志记录**：自动记录方法调用日志
- **性能监控**：监控方法执行时间
- **系统方法扩展**：扩展UIViewController的生命周期方法

**【代码示例】Method Swizzling**
```objc
#import <objc/runtime.h>

@implementation UIViewController (Swizzling)

+ (void)load {
    static dispatch_once_t onceToken;
    dispatch_once(&onceToken, ^{
        Class class = [self class];
        
        SEL originalSelector = @selector(viewWillAppear:);
        SEL swizzledSelector = @selector(swizzled_viewWillAppear:);
        
        Method originalMethod = class_getInstanceMethod(class, originalSelector);
        Method swizzledMethod = class_getInstanceMethod(class, swizzledSelector);
        
        BOOL didAddMethod = class_addMethod(class, originalSelector, 
                                            method_getImplementation(swizzledMethod),
                                            method_getTypeEncoding(swizzledMethod));
        
        if (didAddMethod) {
            class_replaceMethod(class, swizzledSelector,
                               method_getImplementation(originalMethod),
                               method_getTypeEncoding(originalMethod));
        } else {
            method_exchangeImplementations(originalMethod, swizzledMethod);
        }
    });
}

- (void)swizzled_viewWillAppear:(BOOL)animated {
    [self swizzled_viewWillAppear:animated]; // 调用原方法
    NSLog(@"View will appear: %@", NSStringFromClass([self class]));
}

@end
```

### 2.5 类对象与元类

**【理论题】类对象（Class）和元类（Meta Class）的区别？**

答：
- **类对象**：描述实例对象的类型，包含实例方法列表和实例变量
- **元类**：描述类对象的类型，包含类方法列表

对象的isa指针指向类对象，类对象的isa指针指向元类，元类的isa指针指向根元类。

**【场景题】类方法存储在哪里？**

答：类方法存储在元类的方法列表中。

**【代码示例】获取类对象和元类**
```objc
Class class
