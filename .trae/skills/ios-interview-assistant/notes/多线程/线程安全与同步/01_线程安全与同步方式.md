# 线程安全与同步

## 【理论题】
**题目：** 请解释线程安全的概念，以及iOS中常用的线程同步方式有哪些？
**答案：**

**线程安全的概念：**
> 当多个线程同时访问共享资源时，不会出现数据不一致或程序崩溃的情况。

```
线程不安全的例子：
┌─────────────────────────────────────────────────────┐
│  共享变量 count = 10                                 │
│                                                      │
│  线程1: count--  → 读取10 → 写入9                   │
│  线程2: count--  → 读取10 → 写入9  ← 错误！          │
│                                                      │
│  预期结果：count = 8                                  │
│  实际结果：count = 9 （两个线程读到相同的值）            │
└─────────────────────────────────────────────────────┘
```

**常用线程同步方式：**

| 同步方式 | 原理 | 适用场景 | 性能 |
|---------|------|---------|------|
| **@synchronized** | 互斥锁 | 简单场景 | 中等 |
| **NSLock** | 互斥锁 | 通用场景 | 中等 |
| **NSRecursiveLock** | 递归锁 | 递归调用 | 中等 |
| **NSCondition** | 条件锁 | 生产者-消费者 | 中等 |
| **NSConditionLock** | 条件锁（带条件） | 多条件同步 | 中等 |
| **pthread_mutex** | C语言互斥锁 | 高性能场景 | 高 |
| **dispatch_semaphore** | 信号量 | 并发控制 | 高 |
| **OSSpinLock** | 自旋锁 | 短时间临界区 | 极高（已废弃） |
| **os_unfair_lock** | 不公平锁 | 替代OSSpinLock | 极高 |
| **atomic属性** | 原子操作 | 属性读写 | 低（只保证原子性） |

## 【场景题】
**题目：** 什么是死锁？如何避免死锁？

**答案：**

```
死锁的条件（四个必须同时满足）：
1. 互斥条件：资源只能被一个线程占用
2. 请求与保持：线程持有资源并请求新资源
3. 不可抢占：资源只能被主动释放
4. 循环等待：线程A等B，B等A

死锁示例：
┌─────────────────────────────────────────────────────┐
│  线程1：lockA → 等待lockB                            │
│  线程2：lockB → 等待lockA                            │
│                                                      │
│  结果：两个线程互相等待，永远无法继续                   │
└─────────────────────────────────────────────────────┘
```

**避免死锁的方法：**

| 方法 | 说明 |
|------|------|
| **统一加锁顺序** | 所有线程按相同顺序获取锁 |
| **避免嵌套锁** | 一个方法内只获取一个锁 |
| **超时机制** | 等待超时后释放锁 |
| **使用递归锁** | 同一个线程可以重复获取 |
| **使用信号量** | 比互斥锁更灵活 |

## 【代码示例】
```objective-c
// 1. @synchronized（最简单）
- (void)synchronizedDemo {
    @synchronized(self) {
        // 临界区代码
        _count++;
    }
}

// 2. NSLock（通用）
NSLock *lock = [[NSLock alloc] init];

- (void)lockDemo {
    [lock lock];
    // 临界区代码
    _count++;
    [lock unlock];
}

// 3. NSRecursiveLock（递归锁）
NSRecursiveLock *recursiveLock = [[NSRecursiveLock alloc] init];

- (void)recursiveMethod:(int)depth {
    [recursiveLock lock];
    if (depth > 0) {
        NSLog(@"depth: %d", depth);
        [self recursiveMethod:depth - 1];
    }
    [recursiveLock unlock];
}

// 4. NSCondition（条件锁）
NSCondition *condition = [[NSCondition alloc] init];
NSMutableArray *queue = [[NSMutableArray alloc] init];

// 生产者
- (void)produce {
    [condition lock];
    [queue addObject:@"data"];
    [condition signal];  // 唤醒一个等待的线程
    [condition unlock];
}

// 消费者
- (void)consume {
    [condition lock];
    while (queue.count == 0) {
        [condition wait];  // 等待条件满足
    }
    [queue removeLastObject];
    [condition unlock];
}

// 5. dispatch_semaphore（信号量）
// 设置最大并发数为1
dispatch_semaphore_t semaphore = dispatch_semaphore_create(1);

- (void)semaphoreDemo {
    dispatch_semaphore_wait(semaphore, DISPATCH_TIME_FOREVER);
    // 临界区代码
    _count++;
    dispatch_semaphore_signal(semaphore);
}

// 6. 并发控制（最大并发数为3）
dispatch_semaphore_t limitSemaphore = dispatch_semaphore_create(3);

for (int i = 0; i < 10; i++) {
    dispatch_async(dispatch_get_global_queue(0, 0), ^{
        dispatch_semaphore_wait(limitSemaphore, DISPATCH_TIME_FOREVER);
        NSLog(@"任务%d", i);
        sleep(1);
        dispatch_semaphore_signal(limitSemaphore);
    });
}

// 7. atomic vs nonatomic
@property (atomic, strong) NSString *name;  // 原子操作，线程安全但开销大
@property (nonatomic, strong) NSString *name;  // 非原子，性能好但不安全

// 8. 死锁示例
NSLock *lockA = [[NSLock alloc] init];
NSLock *lockB = [[NSLock alloc] init];

// 线程1
dispatch_async(dispatch_get_global_queue(0, 0), ^{
    [lockA lock];
    sleep(1);
    [lockB lock];  // 等待lockB，死锁！
});

// 线程2
dispatch_async(dispatch_get_global_queue(0, 0), ^{
    [lockB lock];
    sleep(1);
    [lockA lock];  // 等待lockA，死锁！
});

// 避免死锁：统一加锁顺序
// 两个线程都先获取lockA，再获取lockB

// 9. 读写锁（pthread_rwlock）
// 多读单写：多个线程可以同时读，但写操作互斥
pthread_rwlock_t rwlock;
pthread_rwlock_init(&rwlock, NULL);

// 读操作
pthread_rwlock_rdlock(&rwlock);
// 读取数据
pthread_rwlock_unlock(&rwlock);

// 写操作
pthread_rwlock_wrlock(&rwlock);
// 写入数据
pthread_rwlock_unlock(&rwlock);

// 10. os_unfair_lock（替代OSSpinLock）
os_unfair_lock_t unfairLock = OS_UNFAIR_LOCK_INIT;

os_unfair_lock_lock(unfairLock);
// 临界区代码
os_unfair_lock_unlock(unfairLock);
```

## 【答题要点】
- 线程安全：多个线程访问共享资源时数据一致
- 线程不安全的根本原因：非原子操作（读取→修改→写入）被打断
- 常用同步方式：@synchronized、NSLock、NSRecursiveLock、NSCondition、dispatch_semaphore
- 死锁条件：互斥、请求与保持、不可抢占、循环等待
- 避免死锁：统一加锁顺序、避免嵌套锁、超时机制
- atomic属性只保证读写操作的原子性，不保证线程安全（复合操作仍有问题）
- 信号量可用于并发控制
- 读写锁适合多读少写场景
- os_unfair_lock是OSSpinLock的替代方案（OSSpinLock存在优先级反转问题）
