# 静态库与动态库详解

## 【理论题】
**题目：** 请解释静态库和动态库的区别，以及动态库代码从哪里获取？
**答案：**

**静态库 vs 动态库：**

```
┌─────────────────────────────────────────────────────┐
│  静态库（.a / .framework静态）                       │
│                                                      │
│  编译时：代码直接复制到App可执行文件中                  │
│  包体积：大（每个App都有一份）                        │
│  启动时：不需要dyld加载（已在可执行文件里）             │
│  优点：启动快，不需要dyld加载                         │
│  缺点：包体积大，升级麻烦                            │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  动态库（.dylib / .framework动态）                   │
│                                                      │
│  编译时：只记录引用，不复制代码                       │
│  包体积：小（多个App共享一份）                        │
│  启动时：需要dyld加载、链接                          │
│  优点：包体积小，升级方便                            │
│  缺点：启动慢，需要dyld加载                         │
└─────────────────────────────────────────────────────┘
```

**为什么减少动态库能优化启动？**

```
动态库越多 → dyld需要加载、链接的文件越多 → 启动越慢

优化策略：
1. 合并动态库：把多个小动态库合并成一个
2. 静态库化：把非必需的动态库改成静态库
3. 移除无用库：删除不用的第三方库

总结：
> 静态库 = 编译时合并到App可执行文件 = 可执行文件大但启动快
> 动态库 = 启动时dyld加载 = 可执行文件小但启动慢
> 系统动态库 = 不占包体积，从共享缓存加载（最优）
> 应用内嵌动态库 = 占包体积，从磁盘加载（最慢）

**注意："动态库包体积小"是不准确的说法！**
- 应用内嵌动态库仍然在App包内，占用包体积
- 动态库只是使可执行文件变小，不是整个App包变小
```

**动态库代码来源：**

```
┌─────────────────────────────────────────────────────┐
│  1. 系统库（UIKit、Foundation等）                     │
│                                                      │
│  来源：dyld_shared_cache（系统共享缓存）                │
│  位置：/System/Library/Caches/com.apple.dyld/        │
│  特点：所有App共享一份，启动时直接映射到内存            │
│  为什么快？系统启动时已预加载到内存                    │
│  加载流程：                                           │
│  - iOS系统启动时合并常用系统库到共享缓存                │
│  - 共享缓存映射到内存，处理好ASLR                      │
│  - App启动时直接映射，不需要磁盘读取和链接              │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  2. 应用内嵌动态库（第三方库）                         │
│                                                      │
│  来源：App包内的Frameworks目录                         │
│  位置：YourApp.app/Frameworks/                       │
│  特点：每个App独立一份，需要从磁盘读取                  │
│  加载过程：解析依赖→找到文件→磁盘读取→链接符号          │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  3. 查找顺序：@rpath → @executable_path/../Frameworks/│
│                → /System/Library/Frameworks/        │
└─────────────────────────────────────────────────────┘
```

**为什么系统动态库比应用内嵌动态库快？**

```
应用内嵌动态库：
├── 从磁盘读取（慢）
├── 链接符号（慢）
├── ASLR处理（慢）
└── 耗时：每个库约几毫秒到几十毫秒

系统动态库（从共享缓存）：
├── 直接内存映射（极快）
├── 不需要链接（已处理好）
├── 不需要ASLR（已处理好）
└── 耗时：几乎可以忽略
```

## 【场景题】
**题目：** 什么时候用静态库，什么时候用动态库？

**答案：**

| 场景 | 选择 | 原因 |
|------|------|------|
| **追求启动速度** | 静态库 | 不需要dyld加载 |
| **追求包体积** | 动态库 | 多个App共享 |
| **系统库** | 动态库 | 系统自带，共享缓存 |
| **第三方库** | 静态库（推荐） | 减少启动时间 |
| **需要热更新** | 动态库 | 可替换更新 |

## 【答题要点】
- 静态库：编译时合并到App，包体积大，启动快
- 动态库：启动时dyld加载，包体积小，启动慢
- 系统库从dyld_shared_cache加载（快）
- 第三方库从App包内Frameworks目录加载（慢）
- 查找顺序：@rpath → @executable_path/../Frameworks/ → /System/Library/Frameworks/
- 优化策略：合并动态库、静态库化、移除无用库
- CocoaPods 1.10+支持静态库化：use_frameworks! :linkage => :static
