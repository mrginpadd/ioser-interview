# 消息机制

## 【理论题】
**题目：** 请解释Objective-C的消息机制，以及它与函数调用的区别？
**答案：**

**Objective-C消息机制：**

`[self doSomething]` 在编译时会被转换为：
```objective-c
objc_msgSend(self, @selector(doSomething));
```

**消息发送流程（5步）：**

1. **快速查找（缓存）**
   - 去`objc_cache`中查找，常用方法会被缓存，速度最快
   - 找到→直接调用；没找到→进入第2步

2. **慢速查找**
   - 根据接收者类型查找：
     - 实例调用→查找**类**的`method_list_t`（实例方法）
     - 类调用→查找**元类**的`method_list_t`（类方法）
   - 查找顺序：本类→父类→...→NSObject
   - 找到→调用并加入缓存；没找到→进入第3步

3. **动态方法解析**
   - 调用`+resolveInstanceMethod:`或`+resolveClassMethod:`
   - 可在运行时动态添加方法，返回YES→重新查找；返回NO→进入第4步

4. **备用接收者**
   - 调用`-forwardingTargetForSelector:`，返回一个对象
   - 返回非nil→转发给该对象重新查找；返回nil→进入第5步

5. **完整消息转发**
   - 调用`-methodSignatureForSelector:`获取方法签名
   - 调用`-forwardInvocation:`将消息包装成`NSInvocation`转发
   - 都没处理→调用`-doesNotRecognizeSelector:`抛出异常

**与函数调用的区别：**

| 特性 | 消息机制（Objective-C） | 函数调用（C/C++） |
|------|------------------------|-------------------|
| 调用方式 | 运行时动态查找 | 编译时确定地址 |
| 灵活性 | 支持动态方法解析、消息转发 | 静态绑定 |
| 性能 | 略慢（运行时查找） | 更快（直接调用） |
| 扩展性 | 支持Method Swizzling | 不支持 |
| 多态 | 天然支持 | 需要虚函数表 |

**Method Swizzling：**
- 通过runtime交换两个方法的实现
- 在方法查找阶段生效，不是消息转发的一部分
- 常用于AOP（面向切面编程）

**代理模式：**
- 是设计模式，不是消息机制的一部分
- 通过协议定义接口，委托对象实现

## 【场景题】
**题目：** 请解释为什么Objective-C可以在运行时动态添加方法？
**答案：**

因为Objective-C的消息机制是**运行时动态查找**的：

```objective-c
@implementation MyClass

+ (BOOL)resolveInstanceMethod:(SEL)sel {
    if (sel == @selector(dynamicMethod)) {
        class_addMethod(self, sel, (IMP)dynamicMethodImplementation, "v@:");
        return YES;
    }
    return [super resolveInstanceMethod:sel];
}

void dynamicMethodImplementation(id self, SEL _cmd) {
    NSLog(@"动态添加的方法被调用");
}

@end

// 使用
MyClass *obj = [[MyClass alloc] init];
[obj performSelector:@selector(dynamicMethod)];  // 运行时动态添加并调用
```

**关键要点：**
- 消息发送在运行时查找方法，编译时不需要方法存在
- 通过`class_addMethod`可以在运行时动态添加方法
- `resolveInstanceMethod:`是动态方法解析的入口

## 【代码示例】
```objective-c
// 消息发送的底层实现
// [obj doSomething] → objc_msgSend(obj, @selector(doSomething))

// 手动调用消息发送
id result = objc_msgSend(self, @selector(doSomething));

// 消息转发示例
- (id)forwardingTargetForSelector:(SEL)aSelector {
    if ([self.delegate respondsToSelector:aSelector]) {
        return self.delegate;
    }
    return [super forwardingTargetForSelector:aSelector];
}

- (NSMethodSignature *)methodSignatureForSelector:(SEL)aSelector {
    NSMethodSignature *signature = [super methodSignatureForSelector:aSelector];
    if (!signature) {
        signature = [self.delegate methodSignatureForSelector:aSelector];
    }
    return signature;
}

- (void)forwardInvocation:(NSInvocation *)anInvocation {
    SEL selector = [anInvocation selector];
    if ([self.delegate respondsToSelector:selector]) {
        [anInvocation invokeWithTarget:self.delegate];
    } else {
        [super forwardInvocation:anInvocation];
    }
}
```

## 【答题要点】
- 消息机制通过objc_msgSend实现，运行时动态查找
- 查找顺序：缓存 → 方法列表 → 动态解析 → 备用接收者 → 完整转发
- 与函数调用的核心区别是动态绑定vs静态绑定
- Method Swizzling在方法查找阶段生效，不是消息转发
- 代理模式是设计模式，与消息机制是不同概念
- 消息机制支持运行时动态添加方法
