# 内存调试

## 【理论题】
**题目：** 请列举常用的内存调试工具和方法，以及如何排查内存泄漏？
**答案：**

**常用内存调试工具：**

```
┌─────────────────────────────────────────────────────┐
│              内存调试工具体系                         │
├─────────────────────────────────────────────────────┤
│  1. Xcode Debug Navigator（基础）                    │
│     - 实时显示内存使用量                              │
│     - 页面关闭后内存不下降 = 有问题                   │
│                                                     │
│  2. Instruments（专业）                              │
│     - Leaks：检测内存泄漏                            │
│     - Allocations：分析内存分配                       │
│     - Zombies：检测僵尸对象                          │
│                                                     │
│  3. Memory Graph Debugger（Xcode自带）               │
│     - 可视化对象引用关系                             │
│     - 直接看到循环引用                               │
│                                                     │
│  4. MallocDebug / Address Sanitizer                 │
│     - 检测内存越界、野指针等                          │
└─────────────────────────────────────────────────────┘
```

**工具对比：**

| 工具 | 用途 | 特点 |
|------|------|------|
| **Xcode Debug Navigator** | 实时监控内存 | 基础，只能看总量 |
| **Instruments - Leaks** | 检测内存泄漏 | 自动扫描泄漏对象 |
| **Instruments - Allocations** | 分析内存分配 | 记录对象创建销毁 |
| **Memory Graph** | 可视化引用关系 | 直接看到循环引用 |
| **Address Sanitizer** | 检测野指针/越界 | 编译时启用 |
| **Zombies** | 检测僵尸对象访问 | 对象释放后保留为Zombie |

## 【场景题】
**题目：** 如何排查一个页面的内存泄漏？

**答案：**

```
排查流程：

1. 基础观察
   - 打开Debug Navigator
   - 进入页面，记录内存值
   - 退出页面，观察内存是否下降
   - 如果不下降 → 有泄漏

2. 使用Memory Graph
   - 进入页面后点击Debug Memory Graph按钮
   - 查看对象引用图
   - 找到应该释放但未释放的对象
   - 查看其引用链，定位循环引用

3. 使用Instruments - Leaks
   - Product → Profile → Leaks
   - 操作App，Leaks自动检测泄漏
   - 查看泄漏对象和调用栈

4. 代码排查重点
   - delegate是否用了weak
   - block是否用了__weak
   - NSTimer是否在dealloc前invalidate
   - 通知是否在dealloc前removeObserver
   - KVO是否在dealloc前removeObserver
```

## 【代码示例】
```objective-c
// 1.dealloc日志监控
- (void)dealloc {
    NSLog(@"%@ 被释放", [self class]);
}
// 如果dealloc不被调用，说明有循环引用

// 2. MLeaksFinder（第三方库，自动检测泄漏）
// 集成后会自动检测ViewController的泄漏
// 当发现泄漏会弹出提示

// 3. FBRetainCycleDetector（Facebook的循环引用检测）
#import <FBRetainCycleDetector/FBRetainCycleDetector.h>
FBRetainCycleDetector *detector = [FBRetainCycleDetector new];
[detector addCandidate:self];
NSSet *cycles = [detector findRetainCycles];
NSLog(@"循环引用：%@", cycles);

// 4. 手动触发内存警告测试
- (void)applicationDidReceiveMemoryWarning:(UIApplication *)application {
    NSLog(@"收到内存警告");
    // 观察哪些对象被释放，哪些没被释放
}

// 5. Xcode配置
// Edit Scheme → Run → Diagnostics
// - 勾选 Memory Management → Malloc Scribble
// - 勾选 Memory Management → Guard Malloc
// - 勾选 Runtime → Address Sanitizer

// 6. 检查代码规范
// 所有的delegate属性
@property (nonatomic, weak) id<SomeDelegate> delegate;

// 所有的block回调
__weak typeof(self) weakSelf = self;
self.completion = ^{
    __strong typeof(weakSelf) strongSelf = weakSelf;
    [strongSelf doSomething];
};

// 所有的timer
- (void)dealloc {
    [self.timer invalidate];
    self.timer = nil;
    [[NSNotificationCenter defaultCenter] removeObserver:self];
}
```

## 【答题要点】
- Xcode Debug Navigator：实时监控内存使用量
- Instruments：Leaks检测泄漏，Allocations分析分配
- Memory Graph Debugger：可视化对象引用关系
- Address Sanitizer：检测野指针、内存越界
- 排查流程：先观察内存是否下降 → Memory Graph看引用关系 → 代码检查
- dealloc日志：验证对象是否被释放
- 常见泄漏点：delegate、block、NSTimer、通知、KVO
- 第三方工具：MLeaksFinder、FBRetainCycleDetector
- 内存警告测试：模拟内存警告观察对象释放
